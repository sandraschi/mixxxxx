# Progress Log, 2026-07-26

Session: source audit, then a fix pass on the video mixer and exporters.
Branch `video`, 18 commits past `2.5.6`, worktree modified.

## Outcome in one line

Video mixing, the reason this fork exists, did not work. It does now, and there is
a test that will fail if it stops working.

## Starting state

Reported as: builds, runs, video mixing implemented across roughly 5000 added lines.

Actual state after tracing every call site:

- Video playback was real. Decode, autoload, render, A/V sync all genuinely wired.
- Video **mixing** could not work. `VideoDecoder` registered with the mixer using
  `m_videoStreamIndex`, the FFmpeg stream index inside the container, which is 0 for
  a normal MP4. Every deck collided in one mixer slot. `blendFrame()` always saw one
  active deck and took the single-source early return. The composite path was
  unreachable.
- The blend curve, had it ever run, was inverted: `fabs(crossfader)` gives pure deck
  A at the centre and full deck B at both extremes.
- Zero tests covered any of the added code.
- No OSC server existed anywhere in `src/`, despite a full control table in the
  README.

## Two corrections to my own earlier claims

Recording these because the failure mode this project keeps hitting is exactly
this: a confident statement becoming evidence in the next review.

**Binary timestamps.** I reported `mixxx.exe` and `mixxx-test.exe` as linked
2026-07-26. They were linked **2026-07-22 23:27**. I had verified the two epoch
values matched each other and then overstated the calendar date.

**"The failing test is unrelated."** I called
`SoundSourceProxyTest.taglibStringToEnumFileType` pre-existing and unrelated to my
changes. Wrong. `git diff 2.5.6 HEAD -- src/sources/soundsourceffmpeg.cpp` shows the
fork added a five-line hunk registering `mkv` and `webm` as supported audio file
types, which is precisely what breaks that assertion. It was the fork's own bug,
sitting in the suite since the hunk landed. Details in ASSESSMENT section 7.2.

The general lesson: "unrelated to my change" needs a `git diff`, not an intuition.

## Known build friction

`mixxx.exe` will not relink while the app is running:

```
LINK : fatal error LNK1104: cannot open file 'mixxx.exe'
```

Close Mixxx before building. `mixxx-lib.lib` and `mixxx-test.exe` relink fine
regardless, so the test suite can be run without closing the app.
